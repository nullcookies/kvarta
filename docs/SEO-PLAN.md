# План: SEO мобильной версии лендинга «Кварта»

## Диагноз (замеры до правок)

`scripts/dev/seo-audit.mjs` по живому HTML и Lighthouse mobile показали:

| # | Проблема | Почему это важно для SEO |
| --- | --- | --- |
| 1 | `<html lang="en">` при полностью русском контенте | Google может считать страницу англоязычной: неверный язык снижает релевантность в русской выдаче, ломает произношение в голосовом поиске |
| 2 | **Контента нет в HTML**: 0 `<h1>`, 0 `<h2>`, 0 `<img>`, текст есть только внутри JSON-пропсов островов в виде `\u0420\u0430…` | Canvas 1.12 жёстко рендерит компоненты как `client="only"` (в коде модуля стоит `@todo` про это). Googlebot JS исполняет, но краулеры соцсетей, мессенджеров и часть поисковых роботов — нет; плюс пустой первый экран = плохие Core Web Vitals |
| 3 | Нет JSON-LD | Для локального бизнеса структурированные данные дают расширенную выдачу: адрес, часы, телефон, цены, рейтинг, хлебные крошки |
| 4 | Нет `sitemap.xml`, в `robots.txt` нет ссылки на него | Медленнее обход, нет явного списка URL |
| 5 | Нет `<main>` (Lighthouse: `landmark-one-main`), внутренние списки свёрстаны абзацами | Семантическая разметка — основа и для доступности, и для понимания структуры роботом |
| 6 | Нет `robots`-меты и `og:locale` | Не задан `max-image-preview:large`, язык OG не указан |
| 7 | CLS 0,688 и LCP 7,0 с на мобильном | Core Web Vitals — фактор ранжирования; острова приходят после загрузки страницы, поэтому контент «прыгает» |
| 8 | Шрифты Oswald/Open Sans без `preload` и без `font-display: swap` | Поздний текст → вклад в FCP/LCP |

## Что реализуем

### Этап 1. Язык и метаданные

1. Добавить русский язык, сделать его языком сайта по умолчанию, перевести
   Canvas-страницу на `ru` → `<html lang="ru">`.
2. В metatag: `robots = index, follow, max-image-preview:large, max-snippet:-1`,
   `og:locale = ru_RU`, `content-language`.

### Этап 2. Структурированные данные (JSON-LD)

Новый модуль `kvarta_seo`, `hook_page_attachments` на главной:

- `CafeOrCoffeeShop` (подтип `LocalBusiness`): название, адрес (Минск, ул. Короля, 9),
  телефон, часы работы (`openingHoursSpecification`), `priceRange`, `image`, `url`,
  `currenciesAccepted`, ссылка на подписку;
- `ItemList` из пяти `Product` с `Offer` (`price`, `priceCurrency: BYN`, `availability`),
  включая подписку как `Product` с `Offer` и `eligibleQuantity`;
- `Organization` и `WebSite` (связка бренда и сайта).

Данные берём из `docs/CONTENT.md` — единого источника текстов и цен.

### Этап 3. Индексация

3. `sitemap.xml` — маршрут в `kvarta_seo`, отдаёт XML со всеми опубликованными
   Canvas-страницами (для лендинга — главная).
4. `robots.txt` — переводим на конфиг модуля `robotstxt` (вместо физического
   файла, который перезаписывается скаффолдом) и добавляем `Sitemap:`.

### Этап 4. Семантика

5. В теме `the_coffee_shop` обернуть контент в `<main id="main-content">`
   (`canvas-page-variant.html.twig`, `page.html.twig`) — это же чинит
   «пропустить к содержимому», который сейчас ведёт в никуда.
6. `<nav aria-label>` для меню, `<ul>/<li>` для списков в колонках доставки.

### Этап 5. Core Web Vitals на мобильном

7. `preload` для двух шрифтов темы + `font-display: swap`.
8. `preload` для картинки первого экрана: модуль находит медиа-URL hero в
   компонентах страницы и добавляет `<link rel="preload" as="image">` — сейчас
   картинка грузится только после гидрации, то есть это чистый выигрыш LCP.
9. Против CLS: зарезервировать высоту секций через CSS (острова до гидрации
   нулевой высоты). Резервируем консервативно, по секциям-анкорам.
10. `theme-color` для мобильных браузеров.

### Этап 6. Проверка

11. `scripts/dev/seo-audit.mjs` — повторный аудит HTML (lang, JSON-LD, sitemap,
    метатеги, семантика).
12. `canvas/scripts/verify-landing.mjs` — DOM-проверка в браузере: один `<h1>`,
    `<img>` с `alt` и размерами, `<main>`, списки, отсутствие горизонтальной
    прокрутки.
13. Повторный Lighthouse mobile и сравнение с исходным замером.

## Чего в этом плане нет и почему (честно)

- **Серверный рендер Canvas-компонентов.** Это корневое решение проблемы №2, но
  в Canvas 1.12 его нет: `AstroIsland::preRenderIsland()` всегда ставит
  `client="only"`, а в комментарии к коду сами авторы пишут, что острова
  гидратируются после полной загрузки страницы, и помечают это `@todo`.
  Варианты на будущее, по возрастанию стоимости:
  1. дождаться SSR в Canvas и включить его (тогда контент приходит в HTML);
  2. собрать SSR-бандл компонентов (`npx canvas build` уже даёт сборку) и
     рендерить разметку Node-сервисом, отдавая её в Drupal;
  3. статический пререндер страницы и отдача готового HTML анонимным
     пользователям (потребует аккуратной гидрации, чтобы не получить дубли).
- **Динамический рендер для ботов** (отдавать роботам другой HTML) не делаем:
  это расходится с правилами Google и граничит с клоакингом.
- **Контент-маркетинг** (блог, тексты под запросы) — вне рамок лендинга.
